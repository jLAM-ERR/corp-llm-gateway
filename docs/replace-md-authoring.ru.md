# Руководство по составлению `replace.md`

Ссылка на план: M8-4.

`replace.md` — это набор правил санитизации на уровне команды. Корп-LLM
применяет эти правила, чтобы найти и заменить специфичные для команды
термины до того, как запрос покинет корп-периметр.

## Расположение файла

По умолчанию шлюз ищет файл `<rules-dir>/<team-id>.md`. Путь
настраивается в `team_config.replace_md_path`.

## Формат

Одно правило на строку. Грамматика строгая — некорректные строки
отклоняются с указанием номера строки.

```
- ORIGINAL = REPLACEMENT
```

Замечания:

- Разделитель — `=`. Легаси-стрелка `→` (U+2192) по-прежнему
  принимается, поэтому существующие файлы продолжают работать. Голый
  ASCII `->` разделителем не является и вызывает ошибку на загрузке.
- **Оборачивайте в обратные кавычки любое значение, содержащее `=`** —
  внутри кавычек `=` считается содержимым, а не разделителем. Значение
  с двоеточием оборачивать **не** нужно; особыми являются только `=`
  (и легаси `→`).
- ORIGINAL и REPLACEMENT можно обернуть в обратные кавычки для наглядности:

  ```
  - `Project Polaris` = `[CONFIDENTIAL_PROJECT]`
  ```

- Строки, начинающиеся с `#`, — комментарии. Как и строки, начинающиеся
  с `<!--` (HTML-стиль для редакторов, отображающих markdown).
- Пустые строки игнорируются.
- Пробелы вокруг токенов обрезаются.
- Поиск — обычная регистронезависимая подстрока, без требования к границе
  слова или идентификатора, будь то ORIGINAL из одного слова или фраза из
  нескольких. Правило `kdir = [X]` заменяет `kdir` и внутри `mkdir`, а не
  только отдельно стоящее `Kdir` или идентификатор вроде `KdirService`;
  `project polaris = [X]` совпадает и внутри `reproject polaristation`.
  **Это меняет поведение существующих словарей**: раньше поиск был
  регистрозависимым; теперь он регистронезависимый, так что после
  обновления совпадений станет больше — проверьте правила, если короткое
  общеупотребимое слово (например, `Acme`) не должно совпадать также с
  `acme` или `ACME`.
- REPLACEMENT подставляется буквально. Поиск регистронезависимый, но на
  выходе всегда точный текст REPLACEMENT из конфигурации — регистр
  подстановки не подстраивается под регистр совпавшего входного текста.
- При пересечении побеждает **более длинный span** — неважно, словарное это
  правило или находка детектора/NER/корп-LLM; правило больше не побеждает
  автоматически более длинную пересекающуюся находку (например, правило
  `Alice = [EMPLOYEE_001]` уступает свой span более длинной находке `Alice
  Smith` → `[PERSON_001]`, поэтому результат — `Contact [PERSON_001] today`,
  а не `Contact [EMPLOYEE_001] Smith today`). Правило всё ещё побеждает, если
  его span совпадает с находкой ТОЧНО.

## Пример файла

```markdown
# Team X replace.md
# Owner: alice@corp.lan

- `Project Polaris` = `[CONFIDENTIAL_PROJECT]`
- `Acme-Internal-CRM` = `[INTERNAL_TOOL]`
- `dr.smith@partnerlab.com` = `[PARTNER_CONTACT]`
- `BadgeID-XYZ-12345` = `[BADGE_ID]`

# Hostnames (двоеточия допустимы без кавычек)
- `db-prod-13.corp.internal` = `[INTERNAL_HOST]`
- `redis-prod:6379` = `[INTERNAL_HOST]`
```

## Обновления на лету

Согласно M1-15: обновления правил вступают в силу при вытеснении из кэша
(по умолчанию 5 мин). Активные диалоги, удерживающие маппинги до
обновления, продолжают их использовать до истечения диалога; новые
вхождения в том же диалоге подхватывают новые правила.

Принудительно обновить можно, уменьшив cache TTL команды или перезапустив
один pod шлюза (rolling restart подхватывает новые правила без потери
трафика).

## Советы по составлению

- **Будьте конкретны**. `- foo = [BAR]` регистронезависимо заменит `foo`
  как обычную подстроку — где угодно, в том числе внутри более длинного слова —
  в каждом запросе. Если `foo` легитимно встречается во многих контекстах, замена
  их сломает.
- **Порядок не влияет на корректность**, но движок сортирует паттерны по
  убыванию длины перед заменой (инвариант M1-9), чтобы предотвратить
  затенение.
- **Пустые ORIGINAL или REPLACEMENT отклоняются** — парсер выдаёт ошибку
  на этапе загрузки.
- **Сначала тестируйте в staging**. Примените правила в
  `gateway-staging.corp.lan` и прогоните тестовый запрос, чтобы
  подтвердить поведение перед промоутом.

## Частые ошибки

| Ошибка | Эффект | Исправление |
|---|---|---|
| Использован голый `->` | Ошибка парсинга на этапе загрузки | Использовать `=` (легаси `→` тоже работает) |
| Голое значение содержит `=` | Разбивается по `=` | Обернуть значение в обратные кавычки |
| Паттерн слишком короткий или общий | Много ложных срабатываний | Добавить кавычки + больше контекста |
| Несколько правил с одним паттерном | Побеждает последнее | Так не делать |
| Строка-комментарий без префикса `#` | Трактуется как правило, парсинг падает | Добавить `#` |
